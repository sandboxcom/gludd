tuple from SESSION.md before invoking Python-dependent Git helpers. Inspect

The target input is BR, supplied as literal branch/ref data. This registered safe
behavioral example deliberately refuses before any Git mutation:

```sh
make git-merge-nc BR=''
```

## Native implementation contract

The foundation and standalone fragment capture literal BR before Make startup
or exported children can evaluate it. A target-specific raw binding preserves
ordinary, recursive/inherited and environment-with-e inputs. The public BR is
unexported; the private alias transports data without shell interpolation.

Before merging, the existing recipe obtains native Git metadata paths and
refuses existing MERGE_HEAD/MERGE_AUTOSTASH, including symlinks. Read-only status
refuses staged, unstaged, mode, untracked or submodule changes. It pins HEAD and
resolves exactly one target commit using native end-of-options handling.

The native merge-tree result, rather than the incoming branch tree alone,
determines paths that may be written. Its first NUL-delimited OID must resolve
as a tree. Native diff-tree provides changed A/M/T paths; native NUL-delimited
ls-files provides ignored files. Exact and both file/directory prefix collisions
refuse before checkout. This includes destinations generated by directory
rename detection. No custom Git parser, option parser or merge engine is added.

Configuration can make result preflight and actual checkout differ. Native
effective nonempty branch mergeOptions and any external merge driver definition
therefore refuse before merge-tree. Empty effective branch options, detached
HEAD and built-in union retain positive controls. Configuration is not edited;
signature verification is not disabled. Native query errors propagate.

The actual merge selects ort, disables autostash, keeps no-ff/no-commit and
no-overwrite-ignore, and consumes the pinned target. A native conflict1 is
aborted only when this invocation opened a matching ordinary MERGE_HEAD, HEAD
is unchanged and autostash remains absent. Existing/foreign state is retained.
Generic17/128 remain native failures; successful abort keeps conflict1; abort23
retains both reasons and returns23. An enclosing Make reports its usual2.

Preflight may create unreachable Git tree/blob objects. Refusal does not promise
object-store byte identity; it preserves index/worktree/refs/checkpoints.
Arbitrary hooks/filters, concurrent configuration/ref mutations and hostile
external filesystem actors are not certified. Existing ownership and Git flow
remain required. This helper is not a development-to-master promotion path.

## Upstream research and decisions

[Native merge-tree](https://git-scm.com/docs/git-merge-tree) supplies the result
tree without index/worktree checkout and may create objects. Inference: compare
that result against HEAD before checking ignored destination collisions.

[Native merge options](https://git-scm.com/docs/git-merge) and
[Git2.54.0 implementation](https://github.com/git/git/blob/v2.54.0/builtin/merge.c)
show branch options parsed before command-line options and strategies appended.
Inference: adding CLI ort alone cannot neutralize configured branch strategies;
refusing nonempty effective options avoids a second parser or hidden overrides.
[Git attributes](https://git-scm.com/docs/gitattributes#_performing_a_three_way_merge)
defines external drivers; the retained fixtures demonstrate their actual side
effects during preflight. Built-in union is separately accepted.

A firsthand [October1 Git mailing-list report](https://gitlist.dev/t/66440)
reproduces ignored-byte loss at a directory-rename destination under both true
and conflict modes, including Git2.54.0. Direct URL retrieval failed with a cache
miss; precise search retrieved the complete original reproduction. The new
confined native controls independently reproduce the relevant loss. This report
does not establish the original index.lock cause or a universal Git defect scope.

The [original2011 protection commit](https://fuchsia.googlesource.com/third_party/git/+/c1d7036b6bfea586a30c6eac672e58e22e5ceaf5)
explains why ignored content can require preservation. The current result-tree
check retains the native flag while adding measured destination protection.
No new scanner, runner, daemon, proof cache, package dependency or cleanup
authority is introduced.
