## Native interface and scope

Public target: git-configure-sandboxcom-https. Its sole new public variable is SANDBOXCOM_HTTPS_VALIDATE_ONLY: exact 1 means offline plan (the default); exact 0 means explicit apply. Other values refuse before Git/GH IO. Remote sandboxcom, host github.com and repository sandboxcom/gludd.git are fixed, not additional inputs.

Safe documented example:

~~~sh
make git-configure-sandboxcom-https SANDBOXCOM_HTTPS_VALIDATE_ONLY=1
~~~

After reviewing that plan, an authorized owner can request:

~~~sh
make git-configure-sandboxcom-https SANDBOXCOM_HTTPS_VALIDATE_ONLY=0
~~~

Plan validates existing repository-local and effective fetch/push bindings, rejects ambiguous or rewritten URLs, and uses git ls-remote --get-url to check the proposed URL without contacting a remote. It performs no authentication or configuration writes. Native refusal remains nonzero.

Apply resolves gh inside the selected recipe, requires an absolute executable, then runs gh auth status --active --hostname github.com. Use ordinary status: the GH manual documents that --json can return zero despite authentication issues. No --show-token, token extraction, gh auth setup-git or global configuration is used. Authentication success is not repository authorization or remote-head proof.

Apply writes only these repository-local settings through native Git:

- credential.https://github.com.helper: an empty reset followed by a shell-quoted absolute gh executable and auth git-credential.
- remote.sandboxcom.url and its explicit push URL: https://github.com/sandboxcom/gludd.git.

The helper is scoped to GitHub in this repository's configuration, not to a single GitHub repository path. Linked worktrees share the common repository configuration.
