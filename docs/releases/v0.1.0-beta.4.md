## Highlights

beta.4 is the **branch-reconciliation and hardening release**. After beta.3 shipped,
a divergent worktree history accumulated over 40+ independent feature branches. beta.4
reconciles that history back onto `development` through tracked, dry-runnable,
Git-native tooling — not scratch scripts — and pairs the reconciliation with a
security/repair wave: fail-closed cryptographic providers, probabilistic data
structure invariants, runtime-checkable SDK boundaries, and enforcement state
isolation for parallel CI runs.

- **Transactional merge-forward workflow** (`development-merge-forward`): divergent
  completed histories are reconciled with current-development content preference,
  structural-conflict rollback, collection gating, and an audited ancestry-only mode
  for superseded patches.
- **Patch-equivalence inventory** (`git-patch-equivalence`): separates already-applied
  patches from genuinely unique branch work before conflict resolution, using
  Git-native patch identity (27 master-relative branches classified in first use).
- **Branch reconciliation inventory** (`branches-unmerged` + `branch-reconcile`):
  every local branch tip not reachable from `development` is inventoried by tracked
  tooling, with optional bounded semantic head summaries (commit subject + first-parent
  changed paths) for machine-consumed JSON with quiet-progress mode.
- **Enforcement state isolation**: multitask dispatch-count, zero-dispatch, and reload
  state are namespaced per run (`GLUDD_MULTITASK_STATE_FILE` et al.) so parallel CI
  shards can no longer consume stale counts from another run.
- **~105,000 tests collected** (105,175 at last S83 count, 1 intentional deselection,
  0 collection errors) — up from 89,542 at the end of beta.3.

  through the orchestrator on the main checkout.
- No breaking changes to the public Python API are introduced by this reconciliation;
  security-domain rejections (fail-closed inputs, provider allowlists) are additive and
  follow the documented zero-downtime rollout patterns.
