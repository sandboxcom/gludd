## Natural-language local configuration

The intended experience is an opt-in, local model turning a plain-language
configuration request into a typed preview that an operator can inspect and read
back. The accepted v0.1.2 state machine ends at `plan_only_opt_in`; every catalog
action retains `apply_supported: false`.
[Natural-language acceptance contract](../features/NATURAL_LANGUAGE_CONFIGURATION_ACCEPTANCE.md#release-states)

This is a non-mutating plan/status capability. Managed-host mutation remains forbidden,
and no approve, apply, verify, or rollback route is admitted. Ollama,
vLLM, and llama.cpp are candidate local profiles only when the exact model,
runtime, prompt, schema, and catalog identities pass strict conformance with no
cloud or alternate-provider fallback.
[Natural-language acceptance contract](../features/NATURAL_LANGUAGE_CONFIGURATION_ACCEPTANCE.md#provider-neutral-local-profiles)

The recorded head is still a pending descendant, and its independently rooted
implementation overlaps the earlier catalog, contracts, planner, collection,
role, and tests. Integration is blocked pending reconciliation; these notes do
not claim that its API, CLI, collection, Molecule path, or live local-model path
is present on the release branch.
[Manifest: conflict and overlap inventory](v0.1.2-integration-manifest.md#conflict-and-overlap-inventory)

## Universal typed-domain work

The candidate defines one strict, provider-neutral typed artifact and adapter
boundary across chemistry/materials QCSchema, code/firmware SARIF, Redfish
hardware observations, and configuration-plan inputs using CUE as the external
validation model. The reviewed adapters normalize those narrow projections into
Choice, Score, or Noul while retaining exact provenance and rejecting ambiguous,
cross-domain, malformed, or non-finite inputs.
[Typed-decision implementation contract](../features/TYPED_DECISION_IMPLEMENTATION_CONTRACT.md#domain-output-adapters)

Its evaluator uses 28 deterministic cases with no model, provider, network,
filesystem, or wall-clock authority. A passing receipt can support only offline
comparison and shadow admission. The capability remains recommendation-only,
has partial branch-local evidence, and is runtime unwired.
[Universal domain-adapter evaluation runbook](../features/TYPED_DECISION_DOMAIN_ADAPTER_EVALUATION_RUNBOOK.md)

Append-only artifacts and receipts make changed semantics and replay mismatches
visible; they do not grant a route, task policy, endpoint, model identity,
credential, deployment, or mutation authority.
[Manifest: typed-domain trust boundary](v0.1.2-integration-manifest.md#universal-typed-domain-adapters)

## OpenJev/Laya offline integration

The OpenJev/Laya candidate is an offline evidence workflow for already-local,
immutable inputs. Its branch-local surface checks the contract, normalizes typed
results, plans compatibility and residency, renders a dry-run, optionally writes
a create-only pre-projection handoff, and replays offline recovery evidence.
[OpenJev/Laya operator runbook](../operations/OPENJEV_LAYA_ADAPTER_RUNBOOK.md)

Runtime admission is not implemented. Recovery execution is not implemented.
The workflow cannot discover endpoints, resolve tags, fetch source or models,
send traffic, apply a projection, preload or evict a model, change profile state,
promote a canary, or invoke post-projection rollback.
[OpenJev/Laya contract](v0.1.2-openjev-laya-adapter-contract.md)

OpenJev endpoints remain operator-owned, and Laya may appear only behind a future
Gludd-owned universal worker. Long-lived evidence is not established: the cited
OpenJev and Laya tracker reports were only days old at the snapshot and define
regression hypotheses rather than an availability or safety record.
[OpenJev/Laya practitioner ledger](../operations/OPENJEV_LAYA_ADAPTER_RUNBOOK.md#practitioner-issues-ledger)

## Compatibility and upgrade notes

- Python 3.11 remains the minimum supported interpreter for this draft; no new minimum is asserted. [Project metadata](../../pyproject.toml)
- This documentation preview does not change v0.1.1, authorize a schema or database migration, or activate a new API, CLI, collection, route, daemon, port, dependency, or model process. [Manifest scope](v0.1.2-integration-manifest.md#scope-and-snapshot-boundary)
- There is no automatic enablement. Existing authoritative behavior remains in place while natural-language intake stays dark, typed-domain readers stay unwired, and OpenJev/Laya candidates stay disabled. [Manifest ZDD boundary](v0.1.2-integration-manifest.md#zdd-and-rollback)
- Integration must use the exact feature-only lists, not whole source branches. Typed-domain work comes first, then OpenJev/Laya, then a human-reviewed natural-language reconciliation, with the manifest refreshed last. [Manifest integration sequence](v0.1.2-integration-manifest.md#next-integration-sequence)
- Immutable digests, exact schema/runtime/profile versions, and original append-only receipts must cross an upgrade unchanged; a mutable tag, branch, endpoint label, or provider name is not compatibility proof. [Manifest trust boundaries](v0.1.2-integration-manifest.md#trust-boundaries)
- Operators should make no runtime change from these notes. Re-evaluate upgrade instructions only after an exact combined SHA has the required receipts and gate evidence. [Manifest proof status](v0.1.2-integration-manifest.md#proof-status)

## Security and privacy

- Natural-language model calls are limited to exact loopback, RFC 1918, or IPv6 unique-local profiles. Redirects, proxies, credential-bearing URLs, mutable aliases, public endpoints, output repair, and cloud fallback fail closed. [Natural-language acceptance contract](../features/NATURAL_LANGUAGE_CONFIGURATION_ACCEPTANCE.md#provider-neutral-local-profiles)
- Provider output remains untrusted after HTTP success. Strict envelope, size, encoding, schema, identity, semantic-grounding, timeout, cancellation, and target-scope checks run before any preview is accepted. [Natural-language acceptance contract](../features/NATURAL_LANGUAGE_CONFIGURATION_ACCEPTANCE.md#security-adversarial-matrix)
- Natural-language receipts retain digests and stable reason codes, not prompts, raw provider output, endpoint URLs, credentials, diffs, or configuration values. [Natural-language acceptance contract](../features/NATURAL_LANGUAGE_CONFIGURATION_ACCEPTANCE.md#coverage-and-evidence-receipts)
- Typed-domain redaction precedes persistence and observation. Unknown fields, cross-request reuse, cross-domain data, digest drift, non-finite values, and changed semantics reject rather than coerce. [Typed-decision implementation contract](../features/TYPED_DECISION_IMPLEMENTATION_CONTRACT.md#domain-output-adapters)
- OpenJev/Laya accepts only already-local immutable evidence. External endpoints and artifacts remain operator-owned, and the workflow must not acquire, mutate, stop, or delete them. [OpenJev/Laya operator runbook](../operations/OPENJEV_LAYA_ADAPTER_RUNBOOK.md#authority-and-preconditions)
- Forum and issue reports are retained as version-scoped failure evidence, not generalized upstream claims; closure does not prove that an arbitrary candidate pin contains a fix. [Manifest practitioner reports](v0.1.2-integration-manifest.md#practitioner-reports)

## ZDD and rollback

Zero-downtime deployment for this preview means keeping the current path
authoritative while new work is dark, unwired, or offline; it is not evidence
that a live rollout or rollback mechanism exists.
[Manifest ZDD and rollback](v0.1.2-integration-manifest.md#zdd-and-rollback)

| Stream | ZDD posture | Fail-closed rollback |
| --- | --- | --- |
| Natural-language configuration | Integrate dark and permit at most one plan-only tenant/profile after exact receipts; managed-host change count stays zero. | Stop new plan intake, preserve status reads and digest-bound receipts, disable the tuple/router/CLI/collection surface, drain read-only calls, and revert reconciled feature commits in reverse order. [Manifest](v0.1.2-integration-manifest.md#zdd-and-rollback) |
| Universal typed-domain adapters | Keep readers unwired and evaluation hermetic; add no provider process, route, port, migration, or policy switch. | Stop shadow evaluation, retain append-only ledger/artifact/receipt evidence, unregister readers, and revert runbook, evaluator, adapters, ledger, and core in reverse feature order. [Manifest](v0.1.2-integration-manifest.md#zdd-and-rollback) |
| OpenJev/Laya | Keep candidates offline and disabled; make no source acquisition, request, model-lifecycle, canary, or recovery change. | Stop offline intake, retain source/profile/report/update receipts, remove only workflow-owned temporary output, and revert the selected commits. Operator-owned endpoints and artifacts stay untouched. [Manifest](v0.1.2-integration-manifest.md#zdd-and-rollback) |

The OpenJev/Laya recovery receipt records a disabled pre-projection boundary; it
is not a callable runtime rollback. Any future mutating or live tranche needs a
generation-bound canary, drain, exact-candidate rollback drill, and retained
original evidence before promotion.
[OpenJev/Laya rollback handoff](../operations/OPENJEV_LAYA_ADAPTER_RUNBOOK.md#phase-6-rollback-and-zdd-handoff)

## Known limitations

- The natural-language head was recorded while its source workstream was still running. Any later descendant remains pending until the manifest inventories it; guessing the head is forbidden. [Manifest snapshot](v0.1.2-integration-manifest.md#scope-and-snapshot-boundary)
- Natural-language foundation and acceptance work have independent roots and overlapping implementations. Automatic conflict resolution cannot prove semantic parity. [Manifest conflict inventory](v0.1.2-integration-manifest.md#conflict-and-overlap-inventory)
- There is no combined release-grade API, Molecule, E2E, exact local-model, installed typed-decision collection, admitted OpenJev/Laya runtime, or rollback-drill receipt. [Manifest proof status](v0.1.2-integration-manifest.md#proof-status)
- Typed-domain and OpenJev/Laya source heads are only feature-review inputs; their branch-local receipts do not prove the future integration SHA. [Manifest proof status](v0.1.2-integration-manifest.md#proof-status)
- The Ansible and schema/runtime reports have multi-year history, but the cited OpenJev/Laya issues were days old. Their long-term availability, security response, and reproducibility remain unknown. [Manifest practitioner reports](v0.1.2-integration-manifest.md#practitioner-reports)
- Contract and runbook links below name documents on the recorded source heads. They may not exist on the target branch until their exact feature-only commits are integrated. [Manifest feature-only selections](v0.1.2-integration-manifest.md#feature-only-selections)
