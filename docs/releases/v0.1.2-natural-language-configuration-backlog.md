# v0.1.2 Natural-Language Configuration Backlog

Status: proposed, not release-complete  
Feature spec: [Natural-Language Configuration Changes](../features/NATURAL_LANGUAGE_CONFIGURATION_CHANGES.md)  
Delivery rule: every item lands test-first as one independently reversible
commit on a feature branch before promotion through `development`.

## Priority and dependency order

This feature is high-impact because it turns Gludd's universal model and Ansible
runtime into a safe user-facing configuration workflow without putting generic
execution under self-improvement. Work is staged so plan-only capability can
ship dark before any mutation path exists.

```text
NLC12-01 corpus/contracts
  -> NLC12-02 catalog
  -> NLC12-03 provider-neutral structured output
  -> NLC12-04 local interpretation/calibration
  -> NLC12-05 deterministic plan/preview
  -> NLC12-06 approval/receipt persistence
  -> NLC12-07 apply/verify/rollback
  -> NLC12-08 API/CLI/collection role
  -> NLC12-09 ZDD and adversarial acceptance
  -> NLC12-10 staged release admission
```

Items may be developed in parallel only when their files are disjoint and their
input contracts are already frozen. Shared schemas, catalog, migrations, and
collection metadata are single-writer surfaces.

## NLC12-01: Freeze contracts and evaluation corpus

Priority: P0  
Dependencies: universal task core and local model profile identities from
v0.1.1.

Deliverables:

- Add failing tests for strict `ConfigurationIntentV1`, operation-specific
  desired-state types, lifecycle states, and canonical digest behavior.
- Add the reviewed, secret-free
  `config/evals/natural_language_configuration_v1.jsonl` corpus with clear,
  ambiguous, unsupported, destructive, injection, multilingual-style phrasing,
  no-op, and rollback cases.
- Add an automated corpus validator for stable IDs, balanced slices, duplicate
  paraphrases, expected outcomes, and absence of obvious secret patterns.
- Record schema, prompt, catalog, model, runtime, and corpus digests in every
  evaluation result.

Acceptance:

- Tests fail before implementation and pass after the strict contracts land.
- Invalid JSON, duplicate keys, unknown fields/actions, missing values,
  traversal, templating syntax, NaN/infinity, target widening, and oversized
  input all fail closed.
- Corpus changes require review and invalidate prior calibration by digest.
- Focused coverage is at least 85% aggregate and 75% per file.

Rollback: remove the additive contracts/corpus before any runtime registration;
no database or execution behavior changes.

## NLC12-02: Implement the immutable action catalog

Priority: P0  
Dependencies: NLC12-01.

Deliverables:

- Add the versioned catalog and deterministic loaders for
  `package.state.v1`, `service.state.v1`, `ini.setting.v1`,
  `sysctl.setting.v1`, and `managed_file.v1`.
- Require typed argument schema, platform support, probe, risk, check/diff,
  idempotence, verification, rollback, secret-field, and ZDD declarations for
  every action.
- Resolve action IDs to reviewed plan builders; never accept an FQCN, Jinja,
  task fragment, path, or command from a model.
- Pin `community.general` and `ansible.posix` through the existing execution-
  environment lock, not vendored code.

Acceptance:

- Catalog hash is stable across key order and rejects duplicate/confusable IDs.
- An incomplete adapter, unsupported platform, unsafe path, unapproved key, or
  missing rollback/ZDD mode cannot register or plan.
- Property tests prove candidate data cannot escape into module names,
  templating, includes, shell, or unmanaged filesystem paths.

Rollback: unregister the catalog version; no accepted plan may be rewritten to
a different catalog digest.

## NLC12-03: Add provider-neutral schema-constrained model calls

Priority: P0  
Dependencies: NLC12-01 and the existing model gateway.

Deliverables:

- Extend the core gateway request contract with a provider-neutral strict JSON
  Schema option and normalized conformance evidence.
- Translate it in Ollama, vLLM, and llama.cpp adapters without leaking provider
  fields to capability code.
- Add startup/runtime probes that distinguish actual constraint enforcement
  from an endpoint merely returning HTTP 200.
- Bound output, time, tokens, retries, and cumulative provider attempts; reject
  prose-wrapped or invalid results rather than repairing them.

Acceptance:

- Contract tests run the same schema vectors through every adapter.
- Known failure shapes from the cited Ollama/llama.cpp reports fail closed.
- Unsupported schema features are rejected before task admission.
- Existing non-structured calls remain wire-compatible.

Rollback: disable the structured-output capability flag; existing gateway calls
retain their previous behavior.

## NLC12-04: Qualify local interpretation and calibrated abstention

Priority: P0  
Dependencies: NLC12-01 through NLC12-03.

Deliverables:

- Implement `ConfigurationIntentAdapter` over `UniversalTaskExecutor` with no
  tools and local-only routing by default.
- Ground all output against authorized target capabilities and the catalog.
- Produce signed per-tuple calibration records and conservative lower confidence
  bounds; ignore model self-confidence for admission.
- Return bounded clarification questions for missing or ambiguous slots and
  typed refusals for dangerous/unsupported intent.

Acceptance:

- At least 80% of clear supported requests are accepted without clarification,
  at least 92% of accepted clear requests have the exact canonical intent, and
  action-family accuracy is at least 97%.
- Ambiguous/unsupported/dangerous abstention recall is at least 99%.
- There are zero unauthorized executions or target widenings in the adversarial
  corpus; malformed candidates are refused 100% of the time.
- Changing any model/runtime/quantization/prompt/schema/catalog/corpus digest
  returns the tuple to shadow mode.

Rollback: disable the tuple or the whole capability; plan requests return a
typed local-interpreter-unavailable result without cloud fallback.

## NLC12-05: Compile and preview deterministic plans

Priority: P0  
Dependencies: NLC12-02 and NLC12-04.

Deliverables:

- Compile typed intents into immutable `ConfigurationPlanV1` using only catalog
  plan builders.
- Bind target/inventory/fact/policy/catalog/execution-environment identities into
  a canonical plan digest.
- Run catalog probes, syntax/lint validation, and supported Ansible check/diff in
  process isolation; bound and redact preview artifacts.
- Refuse stale facts, unsupported preview semantics, absent rollback, or
  unsatisfied minimum healthy capacity.

Acceptance:

- Golden tests prove stable plans and exact invalidation on every bound input.
- Check-mode skips and empty diffs cannot be mistaken for proof of no change.
- Preview cannot mutate managed hosts, leak secrets, or invoke the model's
  suggested command/module.
- A second preview against unchanged facts is byte-identical except timestamps
  kept outside the digest.

Rollback: disable plan compilation registration; previously stored plans remain
readable but cannot advance.

## NLC12-06: Persist digest-bound approvals and receipts

Priority: P0  
Dependencies: NLC12-05, `ApprovalGate`, human todos, and integrity signing.

Deliverables:

- Add an expand-only migration for configuration changes, state transitions,
  approval receipts, execution attempts, and final receipts.
- Bind approval to plan, preview, target, inventory, facts, policy, reviewer,
  expiry, and a one-time nonce.
- Implement optimistic fencing so one change has at most one active apply owner.
- Canonically serialize and sign redacted `ConfigurationChangeReceiptV1`.

Acceptance:

- Missing, expired, replayed, superseded, cross-tenant, or digest-mismatched
  approval always fails closed.
- Restart and concurrent-worker tests preserve monotonic states and one owner.
- Receipt truncation, corruption, missing signature, and field tampering are
  detected before trust.
- Migration works with old and new workers concurrently and has a tested
  expand/contract rollback runbook.

Rollback: stop new intake, drain/rollback active attempts, keep additive tables
for old-reader safety, and disable router registration before later cleanup.

## NLC12-07: Apply, verify, reconcile, and roll back

Priority: P0  
Dependencies: NLC12-05 and NLC12-06.

Deliverables:

- Execute only the approved serialized plan through the existing bounded,
  isolated Ansible runner and locked execution environment.
- Capture preimages, apply canary/batches, verify independently, and require a
  no-change second run before `verified`.
- Stop rollout on any failed health, task, cancellation, timeout, ownership, or
  drift check and run the compensating plan in reverse dependency order.
- Reconcile indeterminate attempts from durable Runner events and live probes
  before retry.

Acceptance:

- Every supported action passes Molecule preview/apply/idempotence/verify/
  rollback scenarios on its declared OS matrix.
- Injected failures at every transition either leave state unchanged or produce
  a verified rollback; rollback failure is a distinct urgent terminal record.
- Child processes, leases, snapshots, and temporary artifacts have one owner and
  bounded cleanup on success, failure, cancellation, and daemon restart.
- Aggregate coverage is at least 85%, every file at least 75%, and lifecycle/
  security/rollback branches target 100%.

Rollback: disable new apply leases; allow current owner to finish verification
or rollback using its pinned artifacts.

## NLC12-08: Add API, CLI, collection, and role surfaces

Priority: P1  
Dependencies: NLC12-04 through NLC12-07.

Deliverables:

- Add the configuration router and `gludd configure` plan/approve/apply/status/
  rollback commands with scoped permissions.
- Add `general_ludd.configuration`, its controller-facing
  `gludd_config_change` module, and `natural_language_change` role.
- Default the role to plan-only, local-only, one host, explicit approval,
  redacted diff, and required ZDD.
- Provide check-mode, argument-spec, collection-import, ansible-lint, and
  Molecule tests plus complete examples and rollback instructions.

Acceptance:

- The role delegates only the daemon call to localhost and never copies prompt
  or credentials to a managed host.
- Check mode calls only plan/status and cannot approve, apply, or rollback.
- API/module/CLI return the same typed state and receipt identity.
- Collection runtime boundary, documentation, and locked dependency checks pass.

Rollback: remove route/CLI/role registration while leaving persisted records
queryable by administrators.

## NLC12-09: Prove ZDD, privacy, and adversarial safety

Priority: P1  
Dependencies: NLC12-07 and NLC12-08.

Deliverables:

- Add two-node canary/rolling acceptance with minimum healthy capacity and
  health-gated advance.
- Prove single-node restart-required changes are refused as non-ZDD.
- Add prompt-injection, secret, Unicode, target-widening, replay, stale-fact,
  symlink, output-amplification, timeout, cancellation, and worker-loss E2E
  cases.
- Add a private-data local-model E2E proving no cloud endpoint is contacted.

Acceptance:

- No accepted rollout violates capacity, target, tenant, policy, or privacy
  constraints.
- Every injected post-apply failure produces verified rollback or an urgent,
  durable `rollback_failed` record.
- Network telemetry demonstrates local-only requests remain local.
- Logs, metrics, API payloads, previews, and receipts contain no seeded secrets.

Rollback: return the feature flag to plan-only and drain active attempts through
their pinned rollback plans.

## NLC12-10: Stage and admit the v0.1.2 feature

Priority: P1  
Dependencies: all earlier items.

Deliverables:

- Deploy schema/catalog/router/role dark, then shadow interpretation, then
  opt-in plan-only, then one canary tenant/action/model tuple, then bounded
  expansion.
- Publish per-tuple corpus evidence, coverage, SBOM/provenance, collection
  artifact digest, migration evidence, ZDD evidence, and rollback drill.
- Document supported actions, explicit non-goals, model qualification, approval
  workflow, recovery, and how operators disable a tuple or the whole feature.
- Add release-readiness checks that require current calibration and immutable
  action/EE identities for every enabled tuple.

Acceptance:

- Full gate and hosted CI pass on the exact development SHA.
- All source and collection files meet 85% aggregate/75% per-file coverage.
- Shadow and plan-only metrics clear admission thresholds with zero unauthorized
  mutation because mutation is still disabled.
- Canary apply, verify, idempotence, deliberate failure, and rollback succeed on
  the exact shipped artifacts before broader enablement.

Rollback: disable intake, revert routing to plan-only, finish or roll back owned
attempts, and retain query access to signed receipts. No tag or artifact is
rebuilt during rollback.

## Release evidence checklist

- [ ] Exact schema, prompt, catalog, corpus, model, runtime, policy, execution-
  environment, collection, and source digests recorded.
- [ ] Clear-request coverage and exact-intent thresholds pass for every enabled
  local tuple.
- [ ] Dangerous/ambiguous abstention and zero-unauthorized-execution thresholds
  pass.
- [ ] Unit, property, integration, Molecule, E2E, chaos, and live-local tests are
  green on the exact release SHA.
- [ ] Aggregate coverage is at least 85% and no implementation file is below
  75%.
- [ ] Ansible check/diff limitations and all cited practitioner findings have
  executable regression coverage.
- [ ] Expand migration, mixed-version operation, ZDD rollout, cancellation,
  recovery, and rollback drill are recorded.
- [ ] Collection artifact, Python artifact, container/execution environment,
  SBOM, provenance, docs, and rollback inputs are built once and promoted by
  digest.

Unchecked boxes are open work. This backlog artifact defines the feature; it is
not evidence that the production capability has been implemented or released.
