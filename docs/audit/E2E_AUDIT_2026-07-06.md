## Gaps & recommendations

1. **`test_environment_e2e.py` is the single largest source of failures (15 of 16).** Fix the `/environment` daemon endpoint first — likely a recent regression given the working tree shows `M src/general_ludd/daemon.py`.
2. **The suite cannot complete in 180s.** Need either (a) a longer timeout for full runs, (b) `-n auto` sharding across more workers, or (c) to mark the heavy live-zai / game-building tests as opt-in. The 957-item suite reached only 45% in 3 minutes on 2 workers.
3. **~40 src/ modules have NO e2e coverage.** The largest cluster is the **observability + connectors + security** trio — all operational-critical and all actively modified in the working tree.
4. **Working-tree churn is unverified.** 11+ src/ files modified, 6+ test files modified, but the e2e run cannot validate them because it timed out at 45%.
5. **Live-API tests silently SKIP.** zai/llamacpp/vllm tests skip without creds; this hides regressions in CI where creds aren't present. Consider a separate "live e2e" lane with required creds.
