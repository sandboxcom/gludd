# OPENBAO_BREAK_GLASS_BACKUP

Break-glass encrypted backup of the OpenBao raft store, scheduled by the gludd
daemon and run as an Ansible role. The deliverable is: even if the gludd host
itself is destroyed, an operator can recover the entire secrets store from any
off-site backup destination that holds (a) the `.gpg` backup file and (b) the
exported GPG private key.

## Architecture

```text
                 ┌──────────────────────────────┐
                 │  gludd daemon (scheduler)    │
                 │  /api/todos/scheduled        │
                 │  cron "0 3 * * *"            │
                 └──────────────┬───────────────┘
                                │ fire
                                ▼
                 ┌──────────────────────────────┐
                 │  openbao_backup.yml          │
                 │  (playbook, hosts: localhost)│
                 └──────────────┬───────────────┘
                                │ include_role
                                ▼
   ┌───────────────────────────────────────────────────────────┐
   │  role: openbao_break_glass_backup                         │
   │                                                           │
   │  Phase 1: probe GPG secret key, create if absent          │
   │  Phase 2: gludd_break_glass module                        │
   │           GET /v1/sys/storage/raft/snapshot               │
   │           -> raw snapshot bytes (temp file)               │
   │  Phase 3: gpg --encrypt -> /var/backups/gludd/openbao/*.gpg│
   │           shred temp file                                 │
   │  Phase 4: gpg --list-packets verify + notify retention    │
   └───────────────────────────────────────────────────────────┘
                 │                              │
                 ▼                              ▼
   ┌──────────────────────────┐    ┌──────────────────────────┐
   │ OpenBao (live)           │    │ /var/backups/gludd/      │
   │ https://127.0.0.1:8200   │    │   openbao/<ts>.gpg       │
   │ token: VAULT_TOKEN       │    │ retention: 30d pruned    │
   └──────────────────────────┘    └──────────────────────────┘
                                            │
                                            │ rsync / S3 / USB
                                            ▼
                                 ┌──────────────────────────┐
                                 │ off-site backup          │
                                 │ (encrypted at rest)      │
                                 └──────────────────────────┘
```

## Why GPG (not just file permissions)

The gludd host is a single machine. Its filesystem permissions protect the
backup at rest ON that host. But the whole point of a break-glass backup is to
move it OFF the host — rsync to a NAS, upload to S3, copy to a USB key — so the
backup survives host loss. Every one of those transports is either:

* **untrusted** (S3, NAS managed by someone else), or
* **physical** (USB, paper) where the storage medium itself can be lost or
  stolen.

File permissions do not apply once the file leaves the host. GPG encryption
covers both: the file is encrypted at rest on the gludd host, AND encrypted in
transit to / at rest on every off-host destination.

The encryption key is a per-host RSA key generated by the role. The operator is
responsible for exporting the private key off-host (see Exporting the private
key below); without that, encrypted backups are unrecoverable if the host is
lost.

## Timer contract

* **Registration:** `POST /api/todos/scheduled` (PSK-gated) with
  `cron="0 3 * * *"`, `work_type="openbao_break_glass"`, `priority="high"`.
* **Persistence:** the entry is a regular SCHEDULED todo, persisted via
  TodoRepository — survives daemon restarts.
* **Default seeding on `make init`:** `scripts/seed_openbao_backup_schedule.py`
  registers the entry if (and only if) OpenBao is initialized — it probes
  `SecretsManager.is_initialized()` before issuing the POST, so an install
  without OpenBao configured does NOT get a broken schedule entry.
* **Per-tick firing:** the existing TodoScheduler (`event_loop/scheduler.py`)
  promotes due SCHEDULED todos to QUEUED child clones; the event loop claims
  them and dispatches the `openbao_break_glass` work type, which runs
  `playbooks/openbao_backup.yml` against localhost.

The daemon scheduler itself is NOT modified. The timer is a regular schedule
entry, registered through the existing API.

## Restore procedure

On a trusted host that holds the exported GPG private key:

```bash
# 1. Import the private key.
gpg --import private-key.asc

# 2. Decrypt the backup, pipe into the new OpenBao raft restore endpoint.
gpg --decrypt openbao-<ts>.gpg \
    | curl --data-binary @- \
           -H "X-Vault-Token: $VAULT_TOKEN" \
           http://new-openbao:8200/v1/sys/storage/raft/restore

# Or via the module:
# - general_ludd.agent.gludd_break_glass:
#     mode: restore
#     openbao_addr: http://new-openbao:8200
#     token: "{{ vault_token }}"
#     restore_source: /path/to/decrypted-openbao.bin
```

`curl` against `/v1/sys/storage/raft/restore` expects a 204 response.

## Retention policy

Backups older than `backup_retention_days` (default 30) are pruned by the
`cleanup old backups` handler, notified at the end of each successful run.

Override:

```yaml
- role: general_ludd.agent.openbao_break_glass_backup
  vars:
    backup_retention_days: 90
```

## Security notes

* All OpenBao tokens are `no_log: true` in both the role tasks and the
  `gludd_break_glass` module argument spec.
* The unencrypted snapshot temp file is shredded immediately after GPG encrypt.
* `openbao_addr` defaults to `https://127.0.0.1:8200`; the role refuses to send
  a token over a plaintext non-loopback transport.
* The GPG private key on the gludd host has `%no-protection` (no passphrase) so
  the role runs unattended — which means anyone who can read `~/.gnupg/` can
  decrypt backups. For air-gap deployments, delete the private key from the
  gludd host after exporting it (see role README).
