What is gludd?

An autonomous coding daemon with an event loop.

You submit a todo, and gludd:

  • Dispatches it to an AI model via Ansible playbooks
  • Runs generated code through a validation pipeline
  • Reviews the result with a separate model
  • Lands the change in git — with evidence

Not a chatbot. Not a copilot. A daemon.
It runs continuously, claims tasks, and produces commits.

Architecture

claim → dispatch → review → reconcile → repeat

The event loop ticks every second:

  1. Claim — dequeue runnable tasks with lease acquisition
  2. Dispatch — run Ansible playbook via the appropriate model
  3. Review — ReturnReviewer model inspects the result
  4. Reconcile — approve, retry, or reject the decision

The Prompt (Snake)

Write a complete, self-contained Python module that implements
the classic Snake game as a headless state machine.
NO external dependencies except the stdlib. NO display code.

Requirements:
- Class name: `Snake`
- `__init__(self, grid_w=20, grid_h=20)`
- `tick(self) -> bool`  # advance one frame
- `input(self, action: str)`  # up/down/left/right
- `render_state(self) -> dict`  # serializable state
- `spawn_food(self)`
- Eating food: grow by 1, increment score, spawn new food

Output ONLY the Python code in a ```python fenced block.

No examples, no shot-prompting, no chain-of-thought. Just the spec.

AutoMemory Subsystem

Three-stage memory pipeline (mirrors Stanford AutoMemory)

Episode → EpisodicMemoryRecorder → "episodic" namespace │ MemoryConsolidator (every 50 eps / 6h) │ "consolidated" namespace (summaries) │ CrossTaskLearner (pattern extraction) │ recommendations + warnings for next task
  • Episodic — raw task-execution records (outcome, tools, takeaway)
  • Consolidated — summarized old episodes by task_type
  • Cross-task — recurring errors + effective strategies across all types

Model gateway is optional. Consolidation works rule-based when no LLM is wired.

How to Use gludd

Quick Start

git clone https://github.com/sandboxcom/gludd.git
cd gludd
make init        # set up directories and dependencies
make bootstrap   # init + lint + test + healthcheck
make help        # list all available make targets

Start the Daemon

# Quick start with defaults (SQLite, no model key)
uv run gludd daemon --port 8000

# With a config directory and model profile
uv run gludd daemon --config-dir ~/.config/general-ludd --port 8000

Submit Todos & Check Status

# Submit a task
uv run gludd todo add "Write a unit test for the login endpoint" --queue core

# Check the queue
uv run gludd todo list --status queued

# Full daemon snapshot
uv run gludd status

Health & Metrics

uv run gludd health
uv run gludd version
curl http://localhost:8000/healthz
curl http://localhost:8000/admin/metrics/export

Creating & Modifying Roles

Roles give gludd new behaviors. They are Ansible roles in general_ludd.agent.

Role Structure

# roles/my_new_role/tasks/main.yml
- name: Gather daemon state
  gludd_facts:
    register: daemon_state

- name: Call the model
  gludd_model_call:
    prompt: "{{ task_prompt }}"
    model_profile: "{{ model_profile | default('zai_coder') }}"
  register: model_result

- name: Write the change
  gludd_git:
    action: commit
    message: "{{ model_result.summary }}"
    files: "{{ model_result.changed_files }}"

Add a molecule/ scenario, register the role, done.

How Role Routing Works

  1. Each todo carries a task_type (code, bug_fix, refactor, ...)
  2. The ModelRouter selects a role based on task_type + routing weights
  3. Roles compose modules into full agent task runs
  4. New roles auto-discover — just drop them in roles/

12 modules (gludd_facts, gludd_model_call, gludd_git, gludd_worktree, ...) → ~90 roles → 49 molecule scenarios

Non-Retrograde Guard

The gate must stay green after every self-edit. No exceptions.

  • make gate is the single source of truth
  • config/ratchet.yml may only shrink (enforced by preflight)
  • Self-modification guards prevent the agent from disabling its own checks

class Episode:
    id: str          # uuid4 hex[:12]
    agent_id: str
    task_type: str   # "code", "bug_fix", "refactor"
    work_type: str
    outcome: str     # success | failure | partial | cancelled
    context: dict[str, Any]
    tools_used: list[str]
    takeaway: str    # what worked
    error_message: str
    duration_seconds: float

class EpisodicMemoryRecorder:
    async def record_episode(self, episode: Episode) -> str:
        await self._repo.set(
            agent_id=episode.agent_id,
            key=episode.id,
            value=json.dumps(_episode_to_dict(episode)),
            namespace="episodic",
        )
        return episode.id
