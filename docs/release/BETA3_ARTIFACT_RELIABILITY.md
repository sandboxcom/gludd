# Beta.3 artifact-pipeline reliability

Research was rechecked on 2026-07-28; the hosted Docker and hidden-coverage
additions were rechecked on 2026-07-29. Dates below are the opening dates of
the user report or discussion; documentation links were accessed on the
corresponding research date.

| Failure mode | External evidence | v0.1.0-beta.3 action |
| --- | --- | --- |
| An older pending run disappears even when `cancel-in-progress` is false. | GitHub's current [concurrency documentation](https://docs.github.com/en/actions/how-tos/write-workflows/choose-when-workflows-run/control-workflow-concurrency) says the default `queue: single` replaces an existing pending run, while `queue: max` retains up to 100. [Community discussion #5435](https://github.com/orgs/community/discussions/5435), opened 2021-09-02, records release/deployment users hitting the default through 2026-02-24. | Keep push and tag runs SHA-scoped so a later development push cannot evict the beta.3 SHA. If branch-scoped serialization is restored, add `queue: max`; `cancel-in-progress: false` alone is not a queue. A cancelled or missing run remains “no verdict,” never green evidence. |
| Matrix jobs reuse an artifact name, or merged artifacts contain the same filename. | The official [artifact v4 migration guide](https://github.com/actions/upload-artifact/blob/main/docs/MIGRATION.md) makes artifacts immutable and warns that `merge-multiple` uses last-writer-wins for duplicate filenames. [upload-artifact issue #478](https://github.com/actions/upload-artifact/issues/478), opened 2023-12-18, shows the resulting `409 Conflict` when several jobs reuse one name. | Preserve the per-platform `gludd-*` artifact names and versioned payload filenames. The release fan-in may merge them only after every name is unique, then must run the 12-category pre-publish gate. Do not restore the old shared matrix artifact pattern. |
| An upload step is green but produced no artifact, or artifact storage rejects the upload. | The official [upload-artifact usage](https://github.com/actions/upload-artifact) says a path with no matches succeeds with a warning by default. [Issue #307](https://github.com/actions/upload-artifact/issues/307), opened 2022-03-13, contains recurring `403` storage-quota reports and user reports that deleted storage was not reclaimed immediately. GitHub documents both [custom retention and artifact deletion](https://docs.github.com/en/actions/how-tos/manage-workflow-runs/remove-workflow-artifacts). | Never treat an upload step's green status as release evidence. The beta.3 fan-in must fail on any missing category; release-producing uploads use `if-no-files-found: error`. Diagnose `403` as quota/storage state, keep transient workflow artifacts on short retention, and do not tag around the failure. |
| A Docker project install cannot resolve a Hatch `force-include` path that exists in the repository. | The official [uv Docker guide](https://docs.astral.sh/uv/guides/integration/docker/#intermediate-layers) separates a cached `--no-install-project` dependency layer from the later project install; Docker's [`COPY` reference](https://docs.docker.com/reference/dockerfile/#copy) confirms that repository paths enter a stage only when copied. Hatch documents [forced inclusion](https://hatch.pypa.io/latest/config/build/#forced-inclusion), while [uv issue #11502](https://github.com/astral-sh/uv/issues/11502), opened 2025-02-14, records a user's difficulty packaging non-source files. | Keep the dependency-only sync cached, but copy every configured wheel force-include into `/app` before the final `uv sync --frozen --no-dev`. A structural regression test derives those source paths from `pyproject.toml`, so a future force-include cannot silently outrun Docker context ordering. |
| A named shard-coverage upload excludes its `.coverage.*` payload because the file is hidden. | The pinned action's [v6 hidden-file documentation](https://github.com/actions/upload-artifact/blob/v6/README.md#uploading-hidden-files) says hidden files are excluded by default. Maintainer [issue #602](https://github.com/actions/upload-artifact/issues/602), opened 2024-08-19, announced the security-motivated breaking change; user [issue #610](https://github.com/actions/upload-artifact/issues/610), opened 2024-09-03, records immediate fallout. | Set `include-hidden-files: true` only on the upload whose path is the exact shard `.coverage.*` filename. Retain the pre-upload `test -s`, `if-no-files-found: error`, unique artifact names, and exact 14-file fan-in count; never enable hidden uploads broadly across the checkout. |
| A gate provisions a real TypeScript transpiler, but a test shard exercising the same hot-reload code silently falls back to regex rewriting. | The setup-node maintainers recommend an explicit runtime in [actions/setup-node](https://github.com/actions/setup-node), and esbuild documents an exact local [npm installation](https://esbuild.github.io/getting-started/). The esbuild maintainer explains in [issue #101](https://github.com/evanw/esbuild/issues/101) that TypeScript grammar needs parsing and backtracking rather than regex deletion; users report CI/runtime failures when the platform package is absent in [issue #3478](https://github.com/evanw/esbuild/issues/3478). | Provision pinned Node 22 and exact esbuild 0.28.1 before both the gate build and every test-shard leg. Workflow regression tests require that provisioning to precede hot-module building and pytest, while candidate syntax/import validation remains fail closed. |
| CPU-derived shard concurrency consumes the memory and virtual-address headroom needed by nested Node and Python processes. | The pytest-xdist project documents that `-n auto` follows available CPUs, while [issue #792](https://github.com/pytest-dev/pytest-xdist/issues/792), opened 2022-07-12, records build users needing an explicit override for their real process budget. Node [issue #32265](https://github.com/nodejs/node/issues/32265), opened 2020-03-14, documents concurrent workers exhausting memory and virtual mappings despite generous heap settings. | Cap hosted shards at two xdist workers through the adaptive runner's numeric override, retain its bounded-respawn and OOM-halving behavior, and leave the remaining runner headroom for nested processes. Do not restore the disabled `GLUDD_TEST_WORKER_MEM_MB`/RLIMIT_AS claim; V8 needs a large contiguous virtual-address range. |
| A release candidate changes `.github/workflows/*`, but the configured HTTPS credential lacks permission to update workflow files. | GitHub's [OAuth scope reference](https://docs.github.com/en/apps/oauth-apps/building-oauth-apps/scopes-for-oauth-apps) states that `workflow` grants permission to add or update Actions workflow files. Users have reported the same remote rejection since 2022 in [Community discussion #26254](https://github.com/orgs/community/discussions/26254). GitHub documents that a write-enabled [repository deploy key](https://docs.github.com/en/authentication/connecting-to-github-with-ssh/managing-deploy-keys) can push over SSH. | Push the exact current branch through the repository-scoped SSH deploy key and an explicit SSH URL; do not assume `GIT_SSH_COMMAND` changes an HTTPS remote's authentication. Apply the busy/rate guards to that branch and verify its remote SHA before dispatching CI. |
| The artifact is listed with the expected name but cannot be retrieved. | [upload-artifact issue #417](https://github.com/actions/upload-artifact/issues/417), opened 2023-07-21, reports a PyInstaller matrix whose correctly named artifacts stalled for more than 30 minutes in both browser and CLI downloads. | A UI listing is not completion evidence. Retain the post-publish `gh release download` smoke tests, execute the Linux binary, inspect the `.deb`, and require the version to match the tag. |
| Separate platform jobs publish or repair the same release independently. | [action-gh-release issue #323](https://github.com/softprops/action-gh-release/issues/323), opened 2023-02-09, demonstrates separate invocations creating confusing duplicate draft and non-draft releases. The action's current [release-asset documentation](https://github.com/softprops/action-gh-release#-uploading-release-assets) says an existing release for the tag is updated with assets. | Keep one fan-in publisher after all platform jobs; matrix jobs upload workflow artifacts only. Repair a partial release only with CI-built files from the tagged SHA, then rerun the same completeness and download checks. |
| A dependency upgrade breaks Molecule only in a real role/scenario layout, while a superficial gate still appears healthy. | The still-open [Molecule issue #4391](https://github.com/ansible/molecule/issues/4391), opened 2025-02-03, has reports from multiple users that Molecule 25 broke working role tests and CI across environments; later comments document workarounds and unexpected migration behavior. | `gate-full` and `gate-all` execute every repository Molecule scenario by name after the real integration and E2E suites. Output is streamed, execution is sequential, and the first non-zero command replaces any stale green terminal marker with `=== GATE: FAILED ===`; invoking or printing a command is never test evidence. |

The release pipeline treats an absent, cancelled, superseded, malformed, or
partially published result as failure. Only the exact tagged commit, a green
required workflow, successful artifact downloads, and the repository's
completeness check constitute release evidence.
