# log_analyzer

**FQCN:** `general_ludd.operations.log_analyzer`

Comprehensive log analysis for gludd — gathers logs from all sources (daemon,
agents, event traces, CI/gate output, OpenShift, systemd/journald, SearX) and
feeds them to model-driven analysis tasks: error clustering, anomaly detection,
agent behavior analysis, performance regression, and root cause suggestion.

Produces structured JSON + markdown reports and a separate chain-of-thought log
(`log_analysis_cot.log`). The legacy `log_analyzer_cot.log` name remains a
byte-identical compatibility artifact. REPORT-ONLY: never mutates the repo.

## Quick Start

```yaml
- hosts: localhost
  gather_facts: true
  roles:
    - role: general_ludd.operations.log_analyzer
      vars:
        enable_model_call: true
        model_profile_error_cluster: "sonnet"
        log_source_dirs: "/var/log/gludd,/tmp/gludd-gate-logs"
```

## Outputs

| File | Format | Description |
|---|---|---|
| `log_analysis_report.json` | JSON | Structured findings with severity, frequency, first/last occurrence |
| `log_analysis_report.md` | Markdown | Human-readable summary with error clusters, anomalies, behavior analysis |
| `log_analysis_cot.log` | Plain text | Canonical audit log: every model call's system prompt, user prompt, and full response |
| `log_analyzer_cot.log` | Plain text | Byte-identical compatibility copy of `log_analysis_cot.log` |

### Finding Structure

Each finding in the JSON report has:
- `timestamp` — first occurrence
- `source_file` — origin log file
- `source_line` — approximate line number
- `error_message` — sanitized error text
- `cluster_id` — hash for grouping similar errors
- `severity` — `critical`, `high`, `medium`, `low`
- `frequency` — count within the analysis window
- `first_seen` / `last_seen` — time range
- `suggested_fix` — model-generated remediation suggestion

## Analysis Tasks

1. **Error clustering** — groups similar errors across all sources by message fingerprint
2. **Anomaly detection** — finds unusual patterns (error rate spikes, slow ticks)
3. **Agent behavior analysis** — identifies premature-stop patterns, dispatch gaps, idle periods
4. **Performance regression** — compares current metrics against a configurable baseline
5. **Root cause suggestion** — for each error cluster, suggests likely root cause
