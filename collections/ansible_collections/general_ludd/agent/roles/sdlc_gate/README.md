# sdlc_gate — AI SDLC Pipeline Gate Role

## Purpose

COMPOSING FAIL-CLOSED gate enforcing SDLC pipeline stage transitions.

Codifies eight AI-DLC research frameworks into runtime enforcement:

1. **AWS Well-Architected ML Lens** — 6 pillars across the ML lifecycle
2. **Microsoft CAF for AI** — 6-phase model (Strategy→Manage)
3. **Google Cloud MLOps** — CI/CD for ML with quality gates
4. **NIST AI RMF** — Govern→Map→Measure→Manage with GenAI action tracking
5. **AI-SDLC Protocol Language** (arXiv:2606.20615) — 2+N team, validation tokens
6. **Agentic Agile-V** (arXiv:2605.20456) — SCOPE-V, conversation-to-contract, evidence bundles
7. **Rethinking SE for Agentic AI** (arXiv:2604.10599) — verification-first lifecycle
8. **AI Assurance Pyramid** (arXiv:2605.23459) — 5-layer testing strategy

## Configuration

Pipeline spec: `config/ai_sdlc.yml`

## Operations

| Operation | Description |
|-----------|-------------|
| `check_stage_entry` | Verify a stage's entry gate is satisfied |
| `check_stage_exit` | Verify a stage's exit gate (all roles complete, checks pass) |
| `advance_stage` | Mark stage complete, produce validation token, emit event |
| `audit_token_chain` | Walk the validation token chain, report missing/broken tokens |
| `list_stages` | Enumerate all stages and their status for a task |
| `validate_pipeline` | End-to-end pipeline config health check |

## Pipeline Stages

```
intake → planning → implementation → review → gate → integration → deployment → operate
```

Each stage has entry gates, required roles, exit gates, validation tokens, and evidence requirements.

### Blocking stages (halt the pipeline on failure):
- `review` — quality + security gates
- `gate` — enforcement + compliance
- `integration` — merge + push verification
- `deployment` — CI + artifact publication

### Non-blocking stages (warn but continue):
- `intake`, `planning`, `implementation`, `operate`

## Design

- **SAFE-BY-DEFAULT:** never mutates the repo; `enable_git_push=false`
- **FAIL-CLOSED:** missing required check = `gate_passed=false`
- **COMPOSING:** ingests per-stage result JSONs from `artifact_dir/`
- **OBSERVABLE:** emits `gludd_message` on every stage transition
- **TIMEOUT-AWARE:** checks elapsed time against `stage_timeouts` config

## Usage

### Check if a stage can begin

```yaml
- name: Verify review stage entry gate
  general_ludd.agent.sdlc_gate:
    operation: check_stage_entry
    stage: review
    task_id: "{{ task_id }}"
    artifact_dir: "/tmp/gludd-sdlc-{{ task_id }}"
  register: entry_check
```

### Enforce stage exit (fail-closed)

```yaml
- name: Enforce review stage exit gate
  general_ludd.agent.sdlc_gate:
    operation: check_stage_exit
    stage: review
    task_id: "{{ task_id }}"
    artifact_dir: "/tmp/gludd-sdlc-{{ task_id }}"
    fail_closed: true
  register: exit_check
  failed_when: not exit_check.gate_passed
```

### Advance to next stage

```yaml
- name: Advance past review stage
  general_ludd.agent.sdlc_gate:
    operation: advance_stage
    stage: review
    task_id: "{{ task_id }}"
    artifact_dir: "/tmp/gludd-sdlc-{{ task_id }}"
    handoff_recipient: "agent_orchestrate"
```

### Audit the token chain

```yaml
- name: Audut validation token chain
  general_ludd.agent.sdlc_gate:
    operation: audit_token_chain
    task_id: "{{ task_id }}"
    artifact_dir: "/tmp/gludd-sdlc-{{ task_id }}"
```

## Evidence Bundles

Each stage requires specific evidence artifacts before advancing. See `config/ai_sdlc.yml`
`evidence_bundles` for the full schema.

Example (review stage):
- `code_reviewer.json` (verdict + findings)
- `gate_triage.json` (gate_passed, per-phase results)
- `security_gate.json` (gate_passed, per-check results)
- `review.json` (synthesized evidence)

## Integration with the Event Loop

The daemon's event loop calls `sdlc_gate` at phase boundaries:
- `_claim_runnable_todos()` → checks entry gates before claiming tasks
- `_review_completed_tasks()` → checks review-stage exit gates
- `_reconcile_decisions()` → checks gate/integration/deployment exit gates
